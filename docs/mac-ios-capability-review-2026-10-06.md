# Mac / iOS 笔记能力复核（2026-10-06）

复核版本：`8cc950a`。本轮只审查源码、构建产物与既有能力，未修改产品代码。以下将源码确认的缺口与尚需原生验证的风险分开。

## 当前基础

已有统一 Markdown 编辑、源码模式、查找替换、表格整理、图片说明与尺寸、公式/图表/提示块、模板、附件预览、章节折叠、专注模式、本机历史、历史归档、HTML/打印、单篇附件包和整库备份。WebDAV 附件上传期间可以续写正文；目录与刷新阶段仍禁写。下一轮优先完善可靠性、设备接力与系统入口。

旧审计中的两项缺口已修正，不能重复列为当前问题：本地目录选择已指定 `fileAccessMode: "scoped"`（`local-vault-adapter.ts:224`）；整库 ZIP 已走原生保存对话框（`markdown-export.ts:47`）。它们仍需要 iOS 文件提供者实际读写、重启和恢复验收。

## 优先处理

### 1. P0：退出和后台保存闭环（源码风险，尚未原生复现丢稿）

Mac 自绘关闭按钮直接调用窗口 `close()`，未等待保存队列；全仓未找到 `onCloseRequested`、`CloseRequested` 或退出保存协调入口。普通本地正文写文件有 650ms 防抖，离线快照有 450ms 防抖。进入后台只尝试写 IndexedDB 快照，失败被忽略，也没有等待物理文件写入的确认。

证据：`src/components/desktop/desktop-app-frame.tsx:34`；`src/App.tsx:656`、`:1222`；`src/services/vault/local-save-coordinator.ts`。

建议：Mac 普通关闭/退出时提交可提交草稿、立即触发待保存任务并等待队列；失败保留可恢复工作副本。iOS 采用持续落盘的恢复日志，进入后台尽早刷新，不依赖系统给异步任务无限时间。界面区分“本机已保存”和“已同步”。

验收：输入后立刻关闭、Cmd+Q、切后台、锁屏及进程终止，重开逐字比较正文；覆盖弱网、磁盘/缓存失败、表格与组合输入。普通退出可协调；强制终止依靠已持久化的恢复日志。

### 2. P1：Mac → iPhone 返回前台时自动检查远端正文（源码确认）

返回前台的处理只拉取文件夹排序。自动同步即使设为 background/reconnect，只要 `pendingSyncCount === 0` 就提前返回。因而已打开的 iPhone 在 Mac 上传正文后，回前台且本机没有修改时，没有正文自动拉取路径，需要手动同步才能发现远端变化。

证据：`src/App.tsx:668-682`、`:2651-2670`。本地 Vault 的文件监听已有，但 WebDAV 没有该监听。

建议：在自动同步模式下，启动、返回前台和恢复网络时增加节流的远端变化检查；手动模式保持用户选择。当前正在编辑的笔记按现有三方合并保护处理，禁止直接覆盖未保存内容。

验收：Mac 修改并上传 → iPhone 回前台自动看到；反方向同样验证；两边同时改、离线后回网、目录移动与附件新增都检查。

### 3. P1：冷启动移除画图模块的静态依赖（构建确认）

本轮重新构建的 `dist/index.html` 仍预加载 `plugin-excalidraw-Bv1mDBlv.js`：4,004,865 bytes，gzip 约 1.39MB，并加载对应 CSS。入口 `index-CYpGgMZM.js` 静态导入该模块的 `_` 导出；该导出实际上是 Vite 的共享预加载函数 `oA`。共享函数被归入可选画图 chunk，使入口也依赖整块画图实现，与“普通笔记首屏不会下载它”的配置注释不一致。

证据：`vite.config.ts:39-40`；本轮 `dist/index.html` 与上述 JS。此外 `src/main.tsx:13` 调用的 `preloadNoteRenderers` 无条件预热编辑、阅读和 Canvas，应按当前路由/笔记类型重新评估。

建议：先把共享运行时函数与可选画图依赖隔离，再按当前笔记类型预热。Mac 原生包的资源来自本机，不应把 gzip 网络体积等同于原生下载成本；但模块解析/执行和内存占用仍需测量。iOS 应记录冷启动到可输入、内存峰值和后台恢复时间。

验收：普通笔记的入口静态依赖图、首屏 preload 和实际资源请求均不包含画图模块；首次打开画图仍成功。保持 HTML 的 SSR 模块按需加载。

### 4. P1：复杂块未保存草稿可恢复（源码确认，产品完善）

公式/Mermaid/提示块编辑输入保存在以 EditorView 为键的 WeakMap 中，只有点击保存或宿主提交时才写回正文。输入后切后台的缓存保存只覆盖正文，不覆盖这份草稿。它能跨同一编辑器的部分重绘保留，但不具备进程重启恢复能力。取消编辑的既有语义应保留。

证据：`src/components/editor/block-edit-session.ts:9-28`；`unified-rich-block.ts:388-424`；`src/App.tsx:656`。

建议：单独持久化未确认草稿，绑定库/笔记/原块版本，恢复时提示继续或放弃。不要为实现恢复而把尚未确认的草稿默默写入正文。表格当前活动单元格也纳入相同验收。

### 5. P1：同步结束状态反映续写后的真实队列（源码确认）

完成日志统计的是调用开始时闭包中的 `notes`，而不是同步结束后重新加载的工作副本。本轮上传使用固定快照，期间的新正文有意留待下一轮；因此开始时没有正文待上传、附件上传期间新输入的场景，结束日志仍可能写“云端与本机一致”。这是状态反馈缺口，不能据此推断正文已丢失；列表的待同步计数另有实时来源。

证据：`src/App.tsx:2596-2600`，与 `:2550-2572` 的排空输入日志/重读工作副本流程对照。

建议：按实际上传结果统计本轮处理量，并按最新队列提示“本轮完成，新增修改仍待同步”；目录、附件、排序和冲突也统一统计。手动模式尤其需要明确剩余项目。

### 6. P2：iOS 日常收集、交付与设备布局（能力完善）

- 系统分享入口：本轮原生项目配置未发现 Share Extension，可先支持 Safari/其他 App 的文字、URL、图片、PDF 保存到明确笔记库的收件箱；随后再做网页正文提取。
- 系统交付：文件保存已有，下一步是系统分享面板和稳定的 PDF 交付；WKWebView 打印、真实 PDF/音视频解码和“文件”App 取回备份还未完成本轮设备验收。
- iPhone 横屏当前显式只开放竖屏；iPad 配置已允许四方向，但不能由配置推断分屏、外接键盘和横屏表格体验已通过。先验证这些具体路径，再开放手机横屏。

证据：`src-tauri/gen/apple/project.yml:45-52`；`src/services/export/markdown-export.ts`；原生配置未包含分享扩展或系统深链注册。

### 7. P2：跨设备历史与附件离线使用

本机历史和手动 JSON 归档已有；历史数据库仍是独立 IndexedDB，未接入自动同步。Mac 的恢复点不能自动在 iPhone 取回。建议提供可选自动历史同步，并明确删除、保留和附件版本边界。

附件预览按需读取已有，但“准备离线使用”需要可见的范围、大小、完成/失败和清理入口。验收采用未打开过的 PDF、图片与音视频，在断网后逐项打开；不能只测试已经命中的缓存。

证据：`src/services/history/note-history.ts:2-4`；`src/components/editor/vault-attachment.tsx`；`src/App.tsx` 的按需资产读取。
