# 真实笔记库备份恢复演练（2026-09-24）

## 范围与方法

- 来源：共享工作区中含 `.obsidian` 的本地笔记库；只读扫描，按本地适配器的规则忽略 `.git`、`.obsidian`、`.swell`、`.swell-trash` 和 `node_modules`。
- 使用应用的 `collectBackupInventory`、`createVaultBackup`、`parseVaultBackup` 与恢复预览函数。把解析后的笔记和可读取附件写入新建的临时空目录，再逐文件对比来源与恢复结果的 SHA-256；测试结束删除临时目录。
- 这项验证覆盖备份清单、ZIP 编解码和文件字节往返。它没有通过应用界面或 Tauri 文件适配器执行真实写入，也不覆盖未被笔记引用、未进入附件缓存的其他文件。
- 另以浏览器回归的独立测试笔记库验证了桌面端“应用导出 ZIP→恢复前预览→空库写入→逐文件 SHA-256 比对”；缺失引用附件时也验证了阻止下载并列出缺失清单。移动端真机和真实笔记库的界面恢复仍需单独验收。
- 使用当前源码构建的 macOS 桌面端，在现有坚果云笔记库的「设置 → 存储维护」点击「备份 ZIP」，直接观察应用的完整性检查结果。该操作只读取笔记和附件，没有触发同步或恢复。

## 第二轮处理与待复验

- 备份扫描现在跳过 Markdown 中指向本机源码行号的普通链接，避免把它们当成 Vault 附件请求远端；嵌入图片仍参与完整性检查。
- Obsidian 的 `![[短文件名]]` 在相对目录读取失败时，会补查笔记库根目录同名文件。独立测试验证了两条分支。
- 单个 WebDAV 附件 GET 返回 404 时，界面现在报告「远端附件不存在」，避免误报成整个笔记库根目录消失。
- 对本地快照重新执行只读演练：88 篇笔记和 4 个可读取附件的 ZIP 往返、逐文件 SHA-256 一致；完整性门槛仍因 6 个找不到同名文件的引用而失败。这个 ZIP 仍不是完整备份。
- 真实坚果云库的第二轮桌面端结果待加载新构建后复验；上表的 12 项是第一轮界面结果，不代表修复后的数量。

本地工作区快照与桌面端打开的坚果云库是两种不同来源，缺失项数量不能直接合并或视为同一份清单。两者目前都未通过完整性门槛。临时 ZIP 仅用于验证本地快照中可读取文件的往返，**不能作为完整备份使用**；未保留 ZIP 或恢复目录。原笔记库没有被写入。由于真实坚果云库未生成完整 ZIP，也没有对它执行恢复验收。

逐项引用路径和同名候选位置保存在共享工作区的本机报告 `backup-rehearsal-issues-2026-09-24.json`，不提交到代码仓库。修正引用或补回附件后，重新运行以下验收，直到完整性门槛通过：

```sh
SWELL_BACKUP_VERIFY_SOURCE=/path/to/vault pnpm exec vitest run src/services/backup/real-vault.rehearsal.test.ts
```

若需要逐项路径报告，可额外设置 `SWELL_BACKUP_VERIFY_REPORT=/path/to/new-report.json`；目标文件必须不存在，以免覆盖旧报告。
