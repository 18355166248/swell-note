# 编辑与预览体验优化

日期：2026-09-13。源码基线：`cff24fd`。本轮按用户要求，由 GPT-6 Astra 独立评审、GPT-5.6 Sol 实现，再回到 Astra 复审和修正。

## 参考与范围

有道云笔记的 [Markdown 官方指南](https://note.youdao.com/help-center/advance_markdown.html) 提供所见即所得、格式工具栏、选文菜单和斜杠菜单；钉钉的 [文档体验设计说明](https://page.dingtalk.com/wow/dingtalk/default/dingtalk/ImasfynJzGJ0114) 强调整合工具、按需展开工具栏与目录。参考公开资料，并非对两个产品的私人文档或全平台客户端做实机对比。

现有 Swell Note 已支持编辑与锁定阅读共用画布、表格、公式、图表、大纲。本轮聚焦：

- HTML 粘贴后保留可见文字、空格、代码、链接和列表结构。
- 粘贴产生的 Markdown 转义在即时画布与锁定阅读正确显示。
- 有序、无序、任务列表的入口、互转及状态反馈，补齐 H4–H6 标题选择。

不将任意块拖拽、多人协作或私有富文本格式加入本轮。

## 初审证据

Astra 独立调用转换器和编辑命令复现：HTML 字面 Markdown 被误解析、格式边界吞空格、连续反引号碰撞、多段列表与列表代码块丢结构、硬换行退为软换行；有序列表点击无序按钮错误变成正文。

关联检查发现即时预览没有处理 Escape、Entity、HardBreak 节点。主代理在浏览器粘贴并切换只读锁定，确认转义反斜杠仍可见；Astra 独立 EditorView 实例确认实体和反斜杠硬换行也显示源码。

## 验收环境

浏览器使用 `http://localhost:4173` 下的独立离线验收缓存。`127.0.0.1:4173` 已存在的配置被验收入口主动拒绝，本轮没有改写它。测试通过已有开发入口显式建立验收笔记，不连接真实云端。初始未跟踪的对比资料与临时诊断测试保持原样。

## 实现与复审结果

Astra 最终独立评审通过，本轮发现的阻断问题已全部修复并复验。生产代码由两位 GPT-5.6 Sol 完成，主代理负责协调、浏览器实测与最终全量验证。

### 已执行的复审循环

1. Astra 初审提出内容保真与列表互转问题，Sol 分工实现。
2. Astra 预复审发现嵌套列表缩进、续行误转和引用内负缩进异常；Sol 修正并补回归。
3. Astra 以真实 Markdown 渲染补反例，发现强调内硬换行、字面实体二次解码、列表首代码块和混排顺序问题；Sol 修正。
4. 新转义策略牵涉独立表格渲染路径，继续检查转义标点、嵌套格式、链接标签及任意反引号代码；同时检查松散列表、子列表独立编号和只修改父项时的后代缩进。

### 浏览器已执行的操作

- 桌面全选有序列表后切为无序，确认列表符号与按钮激活状态。
- 390 × 844 响应式布局下，从选区模式“更多格式”选择有序列表，两行分别显示 1/2，单步撤销恢复无序列表。
- 窄屏粘贴含字面 Markdown、加粗边缘空格、强调内换行、字面实体、多段列表、列表代码块和普通表格的 HTML；切换只读锁定，正文与表格中可见字面符号，不显示转义反斜杠。

第一版全量验证为 720 项通过、1 项跳过，构建通过。此数字仅为中间结果，最终结果以修正全部落地后的执行记录为准。

### 验收边界

本轮未提交或发布代码，未构建安装新的原生应用，未执行完整 Playwright 套件、真实手机输入法和真实云同步。窄屏验收是浏览器响应式布局，不等于真机键盘验证。构建保留原有大 chunk 等提示。

已知既有边界：独立表格渲染仍不是完整 CommonMark 实现，行内代码边界空格存在兼容差异；HTML 内不可读取图片的处理未扩展。笔记列表的摘要仍使用既有文本提取逻辑，部分转义/复杂表格摘要可能显示源码片段，本轮正文编辑与阅读修复没有改摘要算法。
