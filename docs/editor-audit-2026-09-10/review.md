## 修复结论（同日更新）

以上 3 个遗漏均已修复，并已全部转为正式回归用例：

- **P1 嵌套局部取消**：新增 `nestedCutAt` 闭合/重开算法——拆分点穿过嵌套格式节点（Emphasis/Strikethrough/StrongEmphasis）时，在左侧闭合、右侧重开，选区外文字与嵌套格式都保留；拆分点落在链接、图片、行内代码等不可拆结构内部时才退回整段取消。回归用例用 `expectCharFormats` 对每个字符断言渲染语义（见上文建议），不再只断言源码含星号。例如 `**甲*乙丙*丁**` 只选“丙”取消加粗 → 甲/丁保持加粗、乙保持粗+斜、丙只剩斜体。
- **P2 下划线标题**：段落识别改用 `SetextHeading` 前缀匹配，同时覆盖 `SetextHeading1/2`，下划线标记行不参与包裹。
- **P2 ATX 闭合井号**：ATX 标题在段落范围内排除起始 HeaderMark 与末尾闭合井号序列（`/\s+#+\s*$/`），`# 标题 #` 全选加粗得 `# **标题** #`。

修复过程中另发现并修复一个退化用例：`***加粗文字***` 选中全部文字取消斜体时，拆分出的左右片段只剩嵌套加粗的标记字符、没有真实正文，会产出 `****加粗文字****` 空壳标记对；现在两侧均为纯标记时直接整段取消，得 `**加粗文字**`（新增 `onlyMarksBetween` 检查，正文与表格各补一条回归）。

### R4 · P1：链接内局部取消仍然扩大到链接外的正文

输入 `**甲[乙丙](https://example.com)丁**`，只选“丙”取消加粗，实际得到 `甲[乙丙](https://example.com)丁`。未选中的“甲”“丁”都失去加粗。

入口：markdown-input.ts:413。链接整体不可拆并不意味着可以清掉整个外层格式；局部修改不影响选区外内容的约束仍应成立。当前 markdown-input.test.ts 中“拆分点落在链接内部时退回整段取消”测试把这个错误结果固定成通过条件。

修复建议：链接标签内部格式与 URL/图片结构分开处理；如果暂不支持某个范围，保持原文并给出可理解的提示，不得静默扩大操作范围。正式用例应包含链接前后的普通正文，而不只测试一整段链接。

### R5 · P1：空格边界使局部取消失效

入口：markdown-input.ts:418–423。leftText/rightText 原样包括切分点旁空格，直接闭合/重开产生不能按预期配对的分隔符。合法结果可以是 `**甲** 乙 **丙**`，同时保留原始可见空格。

修复建议：切分时把边界空白保留在合适的标记外侧；按 Markdown 分隔符规则重新验证，不得通过 trim 丢掉用户空格。增加中文空格、英文词间空格、标点、软换行、反向选区的参数化语义测试，统一覆盖正文与表格。

## R4/R5 修复结论（同日更新）

两项均已修复并转为正式回归用例，E01 验收补全：

- **R4 链接内局部取消**：不再把「不可拆」当整段取消的理由。拆分序列化（`serializeInlineRange`）把链接/图片的结构标记（`[`、`](url)`、`![`）原样保留，格式标记推进标签内容区：`**甲[乙丙](url)丁**` 只选“丙”取消加粗 → `**甲**[**乙**丙](url)**丁**`。同时新增 `labelBounds`——链接在语法树上 `](`、`URL`、`)` 是独立子节点，用 contentBounds 会把 `](url` 误算进标签。行内代码、自动链接等字面量原子仍不可部分取消：切点落在原子内部时扩展到整颗原子（如 `**甲`xy`乙**` 选 `x` → `**甲**`xy`**乙**`）。原「拆分点落在链接内部时退回整段取消」用例已按新语义重写为逐字符断言。
- **R5 空格边界**：拆分时边界空白挪到标记外侧，`**甲 乙 丙**` 只选“乙” → `**甲** 乙 **丙**`，不再产生空格旁无法配对的标记。
- **标点边界（修复中实测发现）**：闭合标记前是标点、后是文字时按 CommonMark 规则不能闭合（`**甲，**乙**。丙**` 会把整段解析成一个 Strong，操作静默失效）；这种位置不存在「标点保持原格式」的合法写法，实现把边界标点并入中间段一起取消：`**甲，乙。丙**` 只选“乙” → `**甲**，乙。**丙**`（选中文字取消生效，标点为被迫的最小扩大）。格式标记字符（`*`、`]` 等也是 Unicode 标点）不参与此扩展，它们相邻时分隔符自然合并。
- **统一用例**：链接、空格、标点、反向选区、行内代码原子均以逐字符语义断言（`expectCharFormats`）落在正文测试，链接与空格两条同步到表格一致性测试——正文与表格共用同一核心，行为一致。

验证：两组共 109 项通过；全量 623 项通过、1 项跳过；`tsc --noEmit` 无报错。复现页面真实点击核对：R4 得 `**甲**[**乙**丙](https://example.com)**丁**`、R5 得 `**甲** 乙 **丙**`，选区均保留在取消的文字上。未提交。

### R6 · P1：符号字符旁取消加粗仍不生效

输入 `**甲$乙$丙**`，只选“乙”。实际输出 `**甲$**乙**$丙**`，语义解析显示甲、乙、丙全部仍为 StrongEmphasis。

原因：当前 isWord 与扩展条件只检测 Unicode P 类，`$` 属于符号类别，被判成普通文字，与实际解析器的分隔符行为不一致。应复用或严格对齐编辑器所用解析器的标点/符号分类，不再把 `\p{P}` 视为完整规则。回归补美元符号、ASCII 其他符号和相邻标点，检查取消生效、可见文本保留、扩展范围和选区。

### R7 · P1：软换行边界取消加粗仍不生效

输入源码 `**甲\n乙\n丙**`（两处为实际换行，未插空行），只选“乙”。实际输出 `**甲\n**乙**\n丙**`，语义解析同样显示甲、乙、丙全部仍加粗。

原因：serializeInlineRange.wrapRun 的首尾空白处理只匹配 `[ \t]`，换行留在标记内侧，导致重新配对。应保留原换行并把格式闭合在合法位置，例如 `**甲**\n乙\n**丙**`。不能通过直接删除/压缩换行修复；需要同时保留引用、列表的结构前缀。

建议将格式、切点和分隔字符组合为一组参数化语义测试，覆盖空格/Tab/软换行/标点/符号/嵌套节点。基础不变量是可见文本不丢、不增，选中内容的格式确实改变，非必要的范围不受影响；特殊扩展行为应单独断言。R6/R7 仍属于原有格式修改正确性的验收。

## R6/R7 修复结论（同日更新）

两项均已修复，并按上述建议落成参数化语义测试：

- **R6 符号边界**：标点分类不再用 `\p{P}` 近似，与解析器对齐——`@lezer/markdown` 的分隔符判定就是 `/[\p{S}|\p{P}]/u`（`$` `+` `=` 等符号都算标点，已核对 dist 源码）。`**甲$乙$丙**` 只选“乙” → `**甲**$乙$**丙**`，取消生效。
- **R7 软换行边界**：`wrapRun` 的边界空白处理从 `[ \t]` 扩到软换行，换行后的引用结构前缀（`> `）同样留在标记外侧、不包进格式也不删除：`**甲\n乙\n丙**` 只选“乙” → `**甲**\n乙\n**丙**`；引用内 `> **甲\n> 乙\n> 丙**` 只选“乙” → `> **甲**\n> 乙\n> **丙**`（每行 `> ` 前缀原样保留）。选区映射同步跳过被挪出的空白与前缀。
