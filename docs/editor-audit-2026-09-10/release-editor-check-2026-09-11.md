## 二、发现与修复

### 发现 1（产品缺陷，已修复）：拖选跨格落定后，下一次点击单元格被误吞

- 复现：拖选 2×2 选区 → 点正文（高亮正确清除）→ 第一次点击单元格不进编辑态（焦点仍在正文），第二次点击才进入。流程 2 因此把「王」字打进了正文末尾而不是单元格。
- 机制：`onDragUp` 设置 `session.suppressClick = true`，设计意图是吞掉拖选落定后紧随的 click，避免它又进入编辑清掉选区。但跨格拖选时，click 事件的派发目标是按下/抬起位置的**最近公共祖先**（table/tbody），不会派发到任何单元格，单元格上的 `beginEditing` 消费不到这次抑制——标志残留，用户下一次真正的点击被误吞。
- 修复（`src/components/editor/markdown-table-widget.ts`）：`suppressClick` 只抑制当前手势——click 先于定时器派发，`onDragUp` 里用 `setTimeout(0)` 在当前手势结束后复位。拖选落定的 click 仍被吞（落点在单元格时由 `beginEditing` 消费，落点在公共祖先时由复位兜底），之后的真实点击不再受影响。
- 回归：流程 2 覆盖该序列（拖选→正文续写→返回点单元格编辑提交），另用一次性探针验证了「首次点击即进编辑态」（探针已删除，不入库）。

### 发现 2（产品缺陷，已修复）：附件迟到回退追加无任何反馈，且提示无法跨笔记存活

- 约定核对结论（进入条件/归属/取消/位置变更）：
  - **进入条件**：`captureInsertion().insert()` 返回 false——原编辑器实例卸载（切笔记按 `noteRenderIdentity` 重挂载、切阅读模式卸载 MarkdownEditor）或变为只读；`settled` 保证书签只落笔一次，迟到的重复回调返回 false 走回退但不会重复插入（无「取消」入口，不存在已取消操作重新落入正文）。
  - **归属**：`uploadNoteId` 闭包捕获，`formatNoteById` 按 id 查找原笔记追加，经 `appendBlockMarkdown` 补块级空行——追加归属原笔记，不跨笔记误写（探针实测：甲末尾出现引用且有空行分隔，乙零改动）。
  - **位置变更**：回退把插入位置从书签改成了笔记末尾，**之前没有任何提示**（`setAttachmentError(null)`），与验收不变量「回退有准确反馈，不伪装为成功」冲突。
- 修复前误判的修正：第一版把提示加在发起上传的 `NoteEditor` 的 `attachmentError` 上，但切笔记时该组件会被 `NoteDocumentState` 替换卸载，异步回调里的 `setAttachmentError` 落到已卸载实例上，提示丢失（e2e 流程 4 红、探针确认横幅为空）。
- 最终修复（`src/App.tsx` `formatNoteById`）：回退追加的执行点统一发反馈——追加成功后设置跨笔记切换存活的库级横幅 `vaultError`：「「标题」编辑器已切换，附件追加到了笔记末尾」。`workspace.tsx` 只补注释说明提示职责归属，逻辑不变。
- 回归：流程 4（切笔记）与流程 5（切阅读模式）均断言 `p.vault-error` 含「末尾」；流程 5 另验证回退后编辑/阅读两态内容一致（阅读态 img 从本机附件队列解析显示）。

### 测试自身的三处修正（非产品缺陷）

1. 流程 1：受控编辑器的历史分组粗细受 React 同步事务影响（两个回车分成两组、第二个回车与后续输入同组），逐步骤按键级快照属于过度约束——改为「已知快照 + 严格单调 + 有意义操作必达」口径（见第一节末）。
2. 流程 7：附件 URL 本身包含文件名，按纯文本计数会把同一引用的 alt 与 URL 算成两次——改为按引用正则计数。
3. 流程 8：显示模式是全局偏好，刷新后保持刷新前的编辑模式而非默认阅读模式——刷新后显式点「阅读模式」再断言；另修正流程 5 一处断言：img 是替换元素，alt 不进 `textContent`，改断 `alt` 属性。
