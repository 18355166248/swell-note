# 图片与附件插入、异步位置保护、图片操作及撤销

日期：2026-09-11；源码基线：`42b3cd5`（上一轮表格修复已入库）。

## 确认并修复的问题（5 个）

### I1 · 有选区时插入图片会替换选中文字

- 步骤：选中正文里一段文字，插入图片。
- 实际（修复前）：选中文字被图片引用替换，原文丢失。
- 期望：选中文字原样保留，图片插到选区起点。
- 原因：`captureInsertion()` 把书签建成选区区间 `{from, to}`，`insert` 时整体替换。
- 修复：书签永远是零宽插入点（有选区取选区起点 `from`），插入只做 `insert` 不做替换。
- 回归：`markdown-editor.test.tsx`「有文字选区时插入图片不删除选中文字」；浏览器 V1。
- 连带：既有用例「keeps an attachment bookmark…」锁的是旧的替换行为，期望按新约定更新为 `更长的开头 附件目标 结尾`。

### I2 · 插入完成时无条件抢光标与焦点

- 步骤：触发上传后把光标移到别的段落继续写作，等待写入完成。
- 实际（修复前）：完成瞬间光标被拽回插入点并强制聚焦，正在进行的输入被打断。
- 修复：书签记录捕获时的选区对照点（`anchor/head`，随事务映射）。落笔前若选区仍未动，才把光标放到图片之后并滚动可见、聚焦；否则只插入文本，不动选区不聚焦。
- 回归：「等待期间光标移到别处继续写作，插入完成不打断当前光标」「光标仍停在插入点时，完成后光标落在图片之后」；浏览器 V2/V3。

### I3 · 迟到回退追加与末尾段落/表格粘连

- 步骤：插入等待期间切笔记或切阅读模式，写入完成时编辑器已卸载，回退为追加到原笔记末尾；原笔记末行是表格行或普通段落。
- 实际（修复前）：`formatNoteById` 直接 `` `${note.content}${syntax}` `` 拼接——末行是普通段落时图片粘进同一段；末行是表格行时少空行被 GFM 并进表格，图片看似丢失。
- 修复：新增 `appendBlockMarkdown`（`attachment-writer.ts`），按末尾已有换行数补齐块级空行；`App.tsx` 改用之。
- 回归：`attachment-writer.test.ts`「appendBlockMarkdown」4 条（普通段落补空行、表格行不被吞、已有空行不叠加、空正文）。

### I4 · 文件拖入落点不生效

- 步骤：把图片文件拖到正文中间某个位置松手。
- 实际（修复前）：图片落在旧光标处，不在拖放落点。
- 修复：drop handler 用 `view.posAtCoords({x, y}, false)` 取落点，经 `onInsertFiles(files, position)` 传到 `captureInsertion(position)`。
- 回归：「支持显式插入位置（文件拖入的落点），与旧光标无关」。

### I5 · 写入中的第二批插入被静默吞掉

- 步骤：一批附件仍在写入时，再次粘贴/拖入/点插入。
- 实际（修复前）：busy 时编辑器拿不到 `onInsertFiles`，粘贴与拖入直接无反应，无任何反馈。
- 修复：busy 守卫提前到 `handleInsertFiles` 内（用 `attachmentBusyRef`，state 闭包在同一渲染里看不到已开始的批次），命中时给出明确提示「上一批附件仍在写入，请完成后再试」；编辑器 prop 改为 busy 时也传 handler。
- 回归：浏览器 V5（第二批不生效、只插 1 处引用、有提示）。

## 证伪的疑似问题（1 个）

### I6 · 疑似「撤销插入会连带撤销插入前的输入」

- 怀疑：附件插入与此前敲字落在同一撤销时间窗内被合并成一步。
- 实测：红阶段即通过——插入前输入是 `input.type`、附件落笔是 `input.attachment`，history 不跨 userEvent 分组合并，一次撤销只撤图片。
- 处理：不加 `isolateHistory`，如实记录通过（回归用例「撤销插入不连带撤销插入前的输入」保留）。

## 审查通过、无需修复的流程

- **多图顺序稳定**：`writeVaultAttachments` 顺序逐个写入（远端并发敏感），引用顺序 = 选择顺序；多图一次插入是一步撤销/重做（回归「多张图片一次插入作为一步撤销与重做」；浏览器 V4）。
- **部分失败不吞成功项**：单文件失败只记 error，成功文件仍生成引用。
- **图片工具条操作只动当前引用**：删除/尺寸/更换前校验 `sliceDoc(from, to) === sourceText`，过期拒绝覆盖；操作包裹 `isolateHistory.of("full")`，逐次一步撤销（回归 `live-preview.test.ts`「图片工具条操作」4 条，含 `javascript:` 拒绝、空格编码为 `b%20图.png`、只读态仅「查看/重试」）。
- **撤销后无迟到回调重插**：书签单次落笔（`settled`），落笔后 dispose，重复回调返回 false（回归「同一个书签只能落笔一次」）。
- **删除引用不删附件文件**：删除只改 Markdown 引用，附件写入与引用删除无联动。
- **尺寸语法两态一致**：`"480"` title 与 `alt|480` 两种写法，编辑态与阅读态（`parseImagePresentation`）都解析。
- **失效图可识别可重试**：编辑态显示「无法读取图片：alt」+ 查看/重试；阅读态显示 `<code>source</code>` + 重新加载按钮，两处都能看出原始来源。
- **浮层焦点归还**：图片放大浮层关闭时 `origin.current?.focus()` 归还焦点。

## 操作约定（本轮确立）

1. 有选区插图：选中文字原样保留，图片插到选区起点（工具栏/粘贴/拖入一致；拖入落点以松手位置为准）。
2. 等待期间光标未动：完成后光标落在图片之后并滚动可见；光标已移动：只插入、不打断当前输入。
3. 表格单元格编辑中插图：先提交单元格，图片落在表格之后，之间补空行不被并进表格（浏览器 V7）。
4. 并发：第二批不排队，明确提示后由用户重试；远端写入保持串行。
5. 落笔时编辑器不可用（卸载/只读）：`insert` 返回 false，完整应用回退追加到原笔记末尾，经 `appendBlockMarkdown` 补空行。
6. 书签一次性：落笔后即失效，迟到的重复回调不会重复插入。
7. 删除图片引用只删引用，不删附件文件。
